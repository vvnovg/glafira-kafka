# 変更履歴

[CHANGELOG.md](../../CHANGELOG.md)の日本語版です。以前のバージョンは同ファイルを参照してください。各バージョンの内容は、「Glafiraについて」にアップデートのリリースノートとして表示されます。

## 0.5.5
- MCP：ツール引数の `null` は、パラメーターが受け付けない場合にだけ削除されるようになりました。`null` が有効な値である場合は、そのままツールに渡されます。既存のツールの動作は変わりません。この変更は、`null` が「値を削除」を意味するパラメーターに備えたものです。

## 0.5.4
- MCP：「コンパクトなツールセット」を有効にしたクライアントには、変更提案と注記に関する段落を除いたサーバーの指示が送られるようになりました。代わりに、このクライアントにはそれらのツールがなく、必要な変更はチャットで説明するよう記載されます。以前は、モデルが見えないツールを探していました。

## 0.5.3
- TLSエラー：TLSハンドシェイク中にブローカーが接続を閉じた場合、メッセージはポートにTLSがないとは断定しなくなりました。ポートにTLSがない可能性があること、またはクライアント証明書が受け入れられなかったことを示します。後者はmTLSでよくあるケースです。
- MCPがローカルモデル（Qwen、gpt-ossなど）でより安定して動作します。
  - ツールのパラメーターのスキーマに`$ref`参照が含まれなくなりました。一部のサーバー（`qwen3_coder`パーサーを使うvLLM）は、この参照を文字列としてツールに渡していました。
  - JSON文字列として渡されたネストしたオブジェクトが受け付けられ、`null`の値と空のキーは無視されます。それでも引数が合わない場合は、エラーに期待される引数が表示されます。
  - 時間範囲にメッセージがない場合、`read_messages`はタイムゾーンの確認と範囲の拡大を提案します。ツールの説明では、タイムゾーン付きの時刻の渡し方と、正確な1つのキーで絞り込む方法を説明しています。
- 「設定」→「LLMアシスタント（MCP）」：
  - 「応答サイズの上限」：100 KB（デフォルト）、48 KB、24 KBから選べます。コンテキストが小さいローカルモデルでは、小さい値を選んでください。
  - 承認済みの各クライアントに「コンパクトなツールセット」を追加しました。注記と変更提案のツールが含まれなくなり、コンテキストを約1000トークン節約できます。
- ガイド：新しい章「ローカルモデル」を追加しました。モデルを動かせる場所、MacでのQwen3.6とQwen3.8の結果、ハードウェア、Ollama、Qwen CodeとClaude Codeの設定、結果の確認方法を扱います。

## 0.5.2
- LLMアシスタントが読み取るメッセージのマスキングがより徹底されました。
  - テキスト内のCookieと`Authorization`ヘッダー（`Proxy-Authorization`を含む）の値は行末までマスクされるため、すべてのCookie、Digestのパラメーター、AWSの署名が隠されます。
  - `name=value`のペアでは、どの文字で書かれた名前も認識されます。たとえば、接続の独自リストにあるキリル文字のフィールド名です。
  - 文字に続けて書かれたカード番号（`id4111…`）や珍しい区切り方のカード番号、JSON内の負の数や小数として書かれたカード番号も検出されます。
- Describe権限のないトピック：「メッセージ」タブと`read_messages`、`summarize_messages`、`get_group_commit_history`ツールは、「見つかりません」ではなく「この操作を実行する権限がありません」と報告します。
- `get_group_commit_history`：コミット系列を除いてもコミット履歴が100 KBに収まらない場合、アシスタントには空の履歴ではなく、リクエストを絞り込むよう促す「応答が大きすぎます」エラーが返されます。`summarize_messages`は大きなキーでのメモリ使用量が減りました。
- 接続フォーム：
  - 接続フォームを2つ開いていると、一方で選んだLLMアクセスのレベルが表示されませんでした（保存は正しく行われていました）。現在は各フォームにそれぞれのレベルが表示されます。
  - スクリーンリーダーが、本番クラスターのメッセージ内容がLLMプロバイダーに送信されるという警告を読み上げます。
  - MCPの状態を取得できなかった場合は、「メタデータとメッセージ」を選択できない理由を示す注記が表示されます。
  - 「オフ」と「メタデータのみ」のレベルで非表示になっているマスキングのリストが、保存を妨げなくなりました。
- 接続ツリーの`LLM`バッジ：スクリーンリーダーは「LLM」ではなく、「LLMアクセス：メタデータとメッセージ」のように全文を読み上げます。文字のコントラストも高くなりました。
- MCPのログ：接続の一覧を読み込めなかった場合、「『メッセージ』で開く」ボタンに利用できない理由が表示されます。

## 0.5.0
- LLMアシスタントによるメッセージの読み取り。接続のLLMアクセスには「オフ」「メタデータのみ」「メタデータとメッセージ」の3つのレベルがあります。3つ目のレベルでは、アシスタントはMCP経由で次のことができます。
  - 時間範囲またはオフセットでメッセージを読み取る。フィルターは「メッセージ」タブと同じです（`read_messages`）。
  - 内容を含まない時間範囲の概要を見る。パーティション別・時間別の量、頻出するキー、順序が乱れたタイムスタンプ（`summarize_messages`）。
  - `__consumer_offsets`をもとに、コンシューマーグループがいつどのオフセットをコミットしたかを見る（`get_group_commit_history`）。
- 時刻はタイムゾーン付きでのみ渡されます。1回の呼び出しは最大40秒、走査するのは最大100万レコード、返すデータは最大100 KBです。
- アシスタントに渡す前のマスキング：
  - 名前のリスト（標準のリストまたは接続独自のリスト）にあるフィールドの値は`***`に置き換えられます。
  - メールアドレス、カード番号、JWT、認証トークンは、どのテキストでもマスクされます。
  - フィルターはマスク前のデータに対して動作するため、ログにある値でメッセージを見つけられます。
- アクセスレベルとマスキングのリストは、エクスポートもインポートもされません。
- ポリシーキー`mcpMessagesEnabled`はメッセージの読み取りを禁止します。その場合、「メタデータとメッセージ」レベルは「メタデータのみ」として動作します。
- MCPのログ：メッセージの読み取りでは、トピックまたはグループ、走査した件数のうち返した件数、マスクした値の数が表示されます。「『メッセージ』で開く」ボタンは、同じ時間範囲とフィルターで「メッセージ」画面のフォームに入力します。正確に引き継げない場合は、フォームにその旨が表示されます。
- MCP：MCP 2026-07-28プロトコルのクライアント（例：Claude Code 2.1.310）に対応しました。接続時にクライアント名が分かり、承認を求めます。待機中のセッションには「承認」ボタンがあります。すべてのツールは読み取り専用として明示されています（`idempotentHint`）。
- MCPレジストリ（Glama）向けのカタログサーバー`glafira-mcp-catalog`：Dockerイメージと実際のツール一覧を提供し、呼び出しにはデスクトップアプリが必要である旨を返します。READMEは英語になりました（ロシア語版は`README.ru.md`）。
- LLMの提案によるオフセットのリセット：書き込みの前に、グループのメンバー構成を改めて確認します。その間にメンバーがグループに参加したためにブローカーが拒否した場合は、「グループが空ではない」という分かりやすいエラーが表示され、リセットのフォームにはすぐにグループの最新の状態が表示されます。
- インターフェイス：
  - 空のフィールドのプレースホルダーは、入力済みの値と区別できるよう斜体で表示されます。
  - 「メッセージ」画面の開始位置とパーティションのフィールドに、ポインターを合わせると表示されるヒントを追加しました。
  - 接続ツリーの環境とLLMのバッジの上では、通常の矢印ポインターが表示されます。
- ガイド：「LLMアシスタント（MCP）」の章に「メッセージの読み取り」セクションを12言語で追加しました。
