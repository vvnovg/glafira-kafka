# 更新日志

[CHANGELOG.md](../../CHANGELOG.md) 的简体中文版本，更早的版本请参阅该文件。某个版本的内容会在“关于”中作为更新说明显示。

## 0.5.4
- MCP：启用了“精简工具集”的客户端收到的服务器说明不再包含关于变更建议和批注的段落，而是说明该客户端没有这些工具，需要的变更应在聊天中描述。此前，模型会寻找它看不到的工具。

## 0.5.3
- TLS 错误：当 Broker 在 TLS 握手期间关闭连接时，消息不再声称该端口没有 TLS，而是说明该端口可能没有 TLS，或客户端证书未被接受，这是 mTLS 的常见情况。
- MCP 在本地模型（Qwen、gpt-oss 等）上表现更好：
  - 工具参数的 schema 中不再包含 `$ref` 引用，部分服务器（使用 `qwen3_coder` 解析器的 vLLM）曾把这些引用以字符串形式传给工具；
  - 以 JSON 字符串传入的嵌套对象会被接受，`null` 值和空键会被忽略；如果参数仍然不符合要求，错误信息会显示期望的参数；
  - 如果时间窗口内没有消息，`read_messages` 会建议检查时区并扩大窗口；工具说明解释了如何传入带时区的时间，以及如何按单个精确的键过滤。
- “设置”→“LLM 助手（MCP）”：
  - “响应大小上限”：100 KB（默认）、48 KB 或 24 KB——对于上下文较小的本地模型，请选择较小的值；
  - 为每个已批准的客户端提供“精简工具集”：不含批注和修改建议工具，可节省约 1000 个 token 的上下文。
- 指南：新增“本地模型”一章——模型可以在哪里运行、Qwen3.6 和 Qwen3.8 在 Mac 上的结果、硬件、Ollama、Qwen Code 和 Claude Code 的配置，以及如何检查结果。

## 0.5.2
- 对 LLM 助手读取的消息进行更彻底的脱敏：
  - 文本中 Cookie 和 `Authorization` 标头（包括 `Proxy-Authorization`）的值会一直脱敏到行尾，因此所有 Cookie、Digest 参数和 AWS 签名都会被隐藏；
  - `name=value` 键值对中以任何文字书写的名称都能被识别，例如连接自定义列表中用西里尔字母书写的字段名；
  - 紧贴字母的银行卡号（`id4111…`）、以少见方式分组的银行卡号，以及 JSON 中负数和小数形式的银行卡号都能被找到。
- 没有 Describe 权限的主题：“消息”标签页以及 `read_messages`、`summarize_messages` 和 `get_group_commit_history` 工具会报告“无权执行该操作”，而不是“未找到”。
- `get_group_commit_history`：如果即使去掉提交序列，提交历史仍超过 100 KB，助手会收到“响应过大”错误并被建议缩小查询范围，而不是得到空的历史。`summarize_messages` 处理大键时占用的内存更少。
- 连接表单：
  - 同时打开两个连接表单时，其中一个表单中选择的 LLM 访问级别不会显示，尽管保存是正确的；现在每个表单都显示自己的级别；
  - 屏幕阅读器会朗读警告：生产集群的消息内容将发送给 LLM 提供商；
  - 如果无法加载 MCP 状态，会有提示说明为何无法选择“元数据和消息”；
  - 在“关闭”和“仅元数据”级别下隐藏的脱敏列表不再妨碍保存。
- 连接树中的 `LLM` 标记：屏幕阅读器会完整朗读，例如“LLM 访问：元数据和消息”，而不只是“LLM”；文字对比度更高。
- MCP 日志：无法加载连接列表时，“在‘消息’中打开”按钮会说明它为何不可用。

## 0.5.0
- LLM 助手读取消息。连接的 LLM 访问分为三个级别：“关闭”“仅元数据”“元数据和消息”。在第三个级别下，助手可以通过 MCP：
  - 读取时间窗口内或按偏移量的消息，筛选条件与“消息”标签页相同（`read_messages`）；
  - 查看不含内容的时间窗口概览：按分区和时间统计的数据量、常见的键、乱序的时间戳（`summarize_messages`）；
  - 根据 `__consumer_offsets` 查看消费者组在何时提交了哪些偏移量（`get_group_commit_history`）。
- 时间只能带时区传递。每次调用最多运行 40 秒、最多扫描一百万条记录、最多返回 100 KB。
- 在数据发送给助手之前进行脱敏：
  - 名称列表（标准列表或连接自己的列表）中字段的值会被替换为 `***`；
  - 任何文本中的电子邮件地址、银行卡号、JWT 和授权令牌都会被脱敏；
  - 筛选基于未脱敏的数据，因此可以用日志中的值找到消息。
- 访问级别和脱敏列表不会被导出或导入。
- 策略键 `mcpMessagesEnabled` 禁止读取消息：此时“元数据和消息”级别按“仅元数据”工作。
- MCP 日志：读取消息的调用会显示主题或组、已扫描的记录中返回了多少，以及脱敏了多少个值。“在‘消息’中打开”按钮会用相同的时间窗口和筛选条件填写“消息”页面的表单；如果无法准确转移，表单会给出提示。
- MCP：支持 MCP 2026-07-28 协议的客户端（例如 Claude Code 2.1.310）：连接时即获得客户端名称并请求批准。等待中的会话有“批准”按钮。所有工具都明确标记为只读（`idempotentHint`）。
- 面向 MCP 目录（Glama）的目录服务器 `glafira-mcp-catalog`：提供 Docker 镜像和真实的工具列表，调用时会回复需要使用桌面应用。README 改为英文（俄文版为 `README.ru.md`）。
- 按 LLM 建议重置偏移量：写入前会重新检查组的成员。如果 Broker 因组内在此期间加入了成员而拒绝，会显示明确的“组不为空”错误，重置表单也会立即显示组的最新状态。
- 界面：
  - 空字段中的占位文字改为斜体，以免与已输入的值混淆；
  - “消息”页面上的起始位置和分区字段在悬停时显示提示；
  - 连接树中环境和 LLM 标记上方显示普通箭头。
- 指南：“LLM 助手（MCP）”一章新增“读取消息”部分，提供 12 种语言。
