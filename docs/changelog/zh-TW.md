# 變更記錄

[CHANGELOG.md](../../CHANGELOG.md) 的繁體中文版本，較早的版本請參閱該檔案。各版本的內容會在「關於」中作為更新說明顯示。

## 0.5.3
- TLS 錯誤：當 Broker 在 TLS 交握期間關閉連線時，訊息不再宣稱該連接埠沒有 TLS，而是說明該連接埠可能沒有 TLS，或用戶端憑證未被接受，這是 mTLS 的常見情況。
- MCP 在本機模型（Qwen、gpt-oss 等）上表現更好：
  - 工具參數的 schema 中不再包含 `$ref` 參照，部分伺服器（使用 `qwen3_coder` 剖析器的 vLLM）曾把這些參照以字串形式傳給工具；
  - 以 JSON 字串傳入的巢狀物件會被接受，`null` 值和空白鍵會被忽略；如果參數仍然不符合要求，錯誤訊息會顯示預期的參數；
  - 如果時間範圍內沒有訊息，`read_messages` 會建議檢查時區並放寬範圍；工具說明解釋了如何傳入帶時區的時間，以及如何依單一精確的鍵篩選。
- 「設定」→「LLM 助理（MCP）」：
  - 「回應大小上限」：100 KB（預設）、48 KB 或 24 KB——對於上下文較小的本機模型，請選擇較小的值；
  - 為每個已核准的用戶端提供「精簡工具集」：不含註記和修改建議工具，可節省約 1000 個 token 的上下文。
- 指南：新增「本機模型」一章——模型可以在哪裡執行、Qwen3.6 和 Qwen3.8 在 Mac 上的結果、硬體、Ollama、Qwen Code 和 Claude Code 的設定，以及如何檢查結果。

## 0.5.2
- 對 LLM 助理讀取的訊息進行更徹底的遮罩：
  - 文字中 Cookie 和 `Authorization` 標頭（包括 `Proxy-Authorization`）的值會一直遮罩到行尾，因此所有 Cookie、Digest 參數和 AWS 簽章都會被隱藏；
  - `name=value` 配對中以任何文字書寫的名稱都能辨識，例如連線自訂清單中以西里爾字母書寫的欄位名稱；
  - 緊貼字母的卡號（`id4111…`）、以少見方式分組的卡號，以及 JSON 中負數和小數形式的卡號都能被找到。
- 沒有 Describe 權限的主題：「訊息」分頁以及 `read_messages`、`summarize_messages` 和 `get_group_commit_history` 工具會回報「沒有執行此操作的權限」，而不是「找不到」。
- `get_group_commit_history`：如果即使去掉提交序列，提交記錄仍超過 100 KB，助理會收到「回應過大」錯誤並被建議縮小查詢範圍，而不是得到空白的記錄。`summarize_messages` 處理大型鍵時使用的記憶體更少。
- 連線表單：
  - 同時開啟兩個連線表單時，其中一個表單中選擇的 LLM 存取層級不會顯示，儘管儲存是正確的；現在每個表單都會顯示自己的層級；
  - 螢幕閱讀器會朗讀警告：正式環境叢集的訊息內容將傳送給 LLM 供應商；
  - 如果無法取得 MCP 狀態，會有提示說明為何無法選擇「中繼資料和訊息」；
  - 在「關閉」和「僅中繼資料」層級下隱藏的遮罩清單不再妨礙儲存。
- 連線樹中的 `LLM` 標示：螢幕閱讀器會完整朗讀，例如「LLM 存取：中繼資料和訊息」，而不只是「LLM」；文字對比更高。
- MCP 日誌：無法載入連線清單時，「在『訊息』中開啟」按鈕會說明它為何無法使用。

## 0.5.0
- LLM 助理讀取訊息。連線的 LLM 存取分為三個層級：「關閉」「僅中繼資料」「中繼資料和訊息」。在第三個層級下，助理可以透過 MCP：
  - 讀取時間範圍內或依偏移量的訊息，篩選條件與「訊息」分頁相同（`read_messages`）；
  - 檢視不含內容的時間範圍概覽：依分區和時間統計的資料量、常見的鍵、順序錯亂的時間戳記（`summarize_messages`）；
  - 根據 `__consumer_offsets` 查看消費者群組在何時提交了哪些偏移量（`get_group_commit_history`）。
- 時間只能附帶時區傳遞。每次呼叫最多執行 40 秒、最多掃描一百萬筆記錄、最多傳回 100 KB。
- 在資料傳送給助理之前進行遮罩：
  - 名稱清單（標準清單或連線自己的清單）中欄位的值會被替換為 `***`；
  - 任何文字中的電子郵件地址、卡號、JWT 和授權權杖都會被遮罩；
  - 篩選依據未遮罩的資料，因此可以用日誌中的值找到訊息。
- 存取層級和遮罩清單不會被匯出或匯入。
- 原則鍵 `mcpMessagesEnabled` 禁止讀取訊息：此時「中繼資料和訊息」層級會以「僅中繼資料」運作。
- MCP 日誌：讀取訊息的呼叫會顯示主題或群組、已掃描的記錄中傳回了多少，以及遮罩了多少個值。「在『訊息』中開啟」按鈕會以相同的時間範圍和篩選條件填寫「訊息」畫面的表單；如果無法準確帶入，表單會提示。
- MCP：支援 MCP 2026-07-28 協定的用戶端（例如 Claude Code 2.1.310）：連線時即取得用戶端名稱並要求核准。等待中的工作階段有「核准」按鈕。所有工具都明確標示為唯讀（`idempotentHint`）。
- 供 MCP 目錄（Glama）使用的目錄伺服器 `glafira-mcp-catalog`：提供 Docker 映像檔和真實的工具清單，呼叫時會回覆需要使用桌面應用程式。README 改為英文（俄文版為 `README.ru.md`）。
- 依 LLM 建議重設偏移量：寫入前會重新檢查群組成員。如果 Broker 因群組在此期間加入了成員而拒絕，會顯示明確的「群組不是空的」錯誤，重設表單也會立即顯示群組的最新狀態。
- 介面：
  - 空白欄位中的預留位置文字改為斜體，以免與已輸入的值混淆；
  - 「訊息」畫面上的起始位置和分區欄位在指標停留時顯示提示；
  - 連線樹中環境和 LLM 標示上方顯示一般箭頭。
- 使用指南：「LLM 助理（MCP）」一章新增「讀取訊息」區段，提供 12 種語言。
