# Consumer groups

Consumer group — это набор потребителей, которые делят между собой чтение топиков. Kafka отдаёт каждую партицию одному участнику группы и хранит для каждой партиции оффсет, который группа закоммитила. После перезапуска приложения продолжают чтение с этого оффсета.

Откройте [[ui:sidebar.groups]] у подключения в панели [[ui:sidebar.connections]]. Группы одного топика есть также на вкладке [[ui:topics.details.tabGroups]] этого топика. См. [Экран топика](topics.md#topic-details).

## Список групп {#group-list}

В списке — все consumer groups кластера. Столбцы:

- [[ui:groups.list.colGroup]] — ID группы (`group.id`).
- [[ui:groups.list.colState]] — состояние, которое сообщает Kafka, например `Stable` (участники читают), `Empty` (участников нет), `PreparingRebalance` или `CompletingRebalance` (партиции перераспределяются) и `Dead` (группы больше нет).
- [[ui:groups.list.colMembers]] — число активных участников.
- `Assignor` — стратегия распределения партиций, например `range`.
- [[ui:groups.list.colLag]] — суммарный лаг группы. См. [Лаг](groups.md#lag).
- [[ui:groups.list.colTopics]] — топики, в которых у группы есть закоммиченные оффсеты.

Введите текст в поле [[ui:groups.list.search]], чтобы оставить группы, ID которых его содержит; регистр не важен. Список состояний рядом оставляет группы в одном состоянии; [[ui:groups.list.allStates]] снимает этот фильтр. Счётчик показывает, сколько групп показано и сколько их всего.

Участники, assignor и лаг загружаются только для видимых строк, по мере прокрутки. Пока данных нет, в ячейке `…`. Если загрузить их не удалось, в ячейке `—`; наведите на неё указатель, чтобы увидеть причину.

[[ui:groups.list.refresh]] заново загружает список и данные в нём. Если часть брокеров не ответила, появится предупреждение, что список может быть неполным.

## Лаг {#lag}

Лаг — сколько сообщений группа ещё не прочитала. Для каждой партиции это конец лога минус закоммиченный оффсет. Лаг не бывает меньше нуля.

Лаг зависит только от закоммиченных оффсетов. Активный потребитель мог прочитать дальше, чем закоммитил, поэтому настоящий лаг может быть меньше. После следующего коммита группы лаг уменьшится.

Партиция без закоммиченного оффсета показывает [[ui:groups.lag.noCommit]] и не входит в сумму. Суммарный лаг группы показывается как `—`, если у группы нет коммитов вовсе ( [[ui:groups.lag.noCommits]] ) или если оффсеты какой-то партиции не удалось получить ( [[ui:groups.lag.unknown]] ).

Лаг считает оффсеты, а не сообщения. В топиках с compaction или транзакциями часть оффсетов не содержит видимых сообщений, поэтому непрочитанных сообщений может быть меньше, чем показывает лаг.

Значения — снимок на момент загрузки. Чтобы следить за лагом, откройте группу и включите автообновление.

## Детали группы {#group-details}

Нажмите на группу в списке, чтобы открыть её вкладку. Вверху — сводка: состояние, число участников и assignor.

- [[ui:groups.details.autoRefresh]] — [[ui:groups.details.refreshOff]], [[ui:groups.details.refresh5]] или [[ui:groups.details.refresh10]].
- [[ui:groups.details.refresh]] — загрузить заново сейчас.
- [[ui:groups.details.join]] — запустить [consumer-сессию](consumer-sessions.md) в этой группе. В форму сессии попадут ID группы и топики, в которых у неё есть коммиты. Нужна Pro; на подключениях [[ui:common.readOnly]] кнопка недоступна.

[[ui:groups.details.partitions]] — партиции, в которых у группы есть коммиты, и партиции, назначенные её участникам. Над таблицей показан суммарный лаг группы. Столбцы: [[ui:groups.details.colTopic]], [[ui:groups.details.colPartition]], `Committed` (закоммиченный оффсет), `Log end` (конечный оффсет партиции), [[ui:groups.details.colLag]] и [[ui:groups.details.colMember]] (client ID участника, который читает партицию).

[[ui:groups.details.members]] — активные участники: `Client ID`, [[ui:groups.details.colHost]], `Member ID` и [[ui:groups.details.colAssignment]] (партиции участника в виде `topic:partition`). Для группы без участников показывается [[ui:groups.details.noMembers]].

Во втором ряду — [[ui:groups.details.resetOffsets]] и [[ui:groups.details.deleteGroup]]. На подключениях только для чтения этот ряд скрыт.

## Сброс оффсетов {#reset-offsets}

Сброс оффсетов передвигает закоммиченные оффсеты группы. После этого группа перечитывает сообщения или пропускает их. Сбросить оффсеты можно только у группы без активных участников, в состоянии `Empty`. Иначе участники перезапишут новые оффсеты своими коммитами. Сначала остановите приложения группы.

1. На вкладке группы нажмите [[ui:groups.details.resetOffsets]]. Пока в группе есть участники, кнопка недоступна, причина показывается.
2. Выберите [[ui:groups.reset.strategy]]. См. [Стратегии сброса](groups.md#reset-strategies).
3. Выберите [[ui:groups.reset.scope]]. См. [Область сброса](groups.md#reset-scope).
4. Нажмите [[ui:groups.reset.preview]].
5. Проверьте таблицу и нажмите кнопку применения. На ней указано, сколько партиций изменится.

Предпросмотр ничего не меняет. Для каждой партиции он показывает топик, партицию, [[ui:groups.reset.colCurrent]] (закоммиченный оффсет), [[ui:groups.reset.colNew]] (целевой оффсет) и `Low / High` (первый и конечный оффсеты партиции). Партиция, для которой целевой оффсет вычислить нельзя, помечена [[ui:groups.reset.noTarget]] с причиной. Такие партиции пропускаются.

Применяется только план, показанный в предпросмотре. Любое изменение формы скрывает предпросмотр, и нужно снова нажать [[ui:groups.reset.preview]]. На prod-подключении применение просит ввести имя подключения; на остальных выполняется сразу.

Перед применением приложение ещё раз проверяет, что в группе нет участников. После применения [[ui:groups.reset.result]] перечисляет партиции с новым оффсетом или ошибкой.

Сброс можно подготовить и из сообщения: см. [Сбросить группу к сообщению](browse.md#reset-group-here). [[ui:common.close]] закрывает панель сброса.

## Стратегии сброса {#reset-strategies}

[[ui:groups.reset.strategy]] задаёт целевой оффсет для каждой партиции из области сброса:

- [[ui:groups.reset.strategyEarliest]] — первый оффсет, который ещё хранится. Группа перечитает всё, что есть в топике.
- [[ui:groups.reset.strategyLatest]] — конец партиции. Группа пропустит всё накопленное и будет читать только новые сообщения.
- [[ui:groups.reset.strategyTimestamp]] — первое сообщение, записанное в момент из поля [[ui:groups.reset.timestamp]] или позже. В партициях без более новых сообщений целевой оффсет — конец.
- [[ui:groups.reset.strategyOffset]] — оффсет из поля [[ui:groups.reset.offset]], целое число от 0, одинаковый для всех партиций. Если в партиции такого оффсета нет, берётся её первый или конечный оффсет.
- [[ui:groups.reset.strategyShift]] — сдвигает закоммиченный оффсет на число из поля [[ui:groups.reset.shift]]. Отрицательное число — перечитать N сообщений назад, положительное — пропустить N сообщений. Результат не выходит за первый и конечный оффсеты. Партиции без закоммиченного оффсета сдвинуть нельзя, они пропускаются.

Время — местное, с секундами. Kafka находит оффсет по меткам времени сообщений.

## Область сброса {#reset-scope}

[[ui:groups.reset.scope]] задаёт, какие партиции сбрасываются. У остальных партиций оффсеты не меняются.

- [[ui:groups.reset.scopeAll]] — все партиции, в которых у группы есть закоммиченные оффсеты. Если коммитов у группы ещё нет, выберите топики.
- [[ui:groups.reset.scopeTopics]] — все партиции перечисленных топиков, в том числе без коммитов. Разделяйте имена запятыми, пробелами или переводами строк. Так можно задать группе, с какого места начать читать новый для неё топик.
- [[ui:groups.reset.scopePartitions]] — только перечисленные партиции. Укажите их в поле [[ui:groups.reset.partitionsLabel]] в виде `topic:partition` через запятую или пробел, например `orders:0, orders:3`.

## Удаление группы {#delete-group}

Удаление группы стирает все её закоммиченные оффсеты. Удалить можно только группу без участников, в состоянии `Empty`.

1. На вкладке группы нажмите [[ui:groups.details.deleteGroup]]. Пока в группе есть участники, кнопка недоступна.
2. Для подтверждения введите ID группы. На prod-подключении введите ещё и имя подключения.
3. Нажмите [[ui:common.delete]].

После удаления вкладка группы закрывается. Если приложение с этим `group.id` запустится снова, Kafka создаст группу заново. Без закоммиченных оффсетов приложение начнёт с того места, которое задаёт его параметр `auto.offset.reset`: с начала или с конца.

На подключениях [[ui:common.readOnly]] кнопка скрыта.
