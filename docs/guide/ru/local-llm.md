# Локальные модели

Ассистенту не обязательно работать в облаке: Glafira одинаково отвечает любому MCP-клиенту, а клиент может обращаться к модели в вашей сети или на вашем компьютере. Глава о том, где может работать модель, какое железо нужно для локальной модели, как подключить её к Glafira и как проверить результат. Как устроен сам доступ ассистента к кластерам — в главе [LLM-ассистенты (MCP)](llm-mcp.md#how-it-works).

## Где работает модель {#where}

1. **Облачная модель** (Claude, GPT и другие): самая сильная, но запросы с метаданными кластеров, а с уровнем [[ui:connections.form.llmLevel.messages]] и с содержимым сообщений, уходят за пределы вашей сети. Во многих компаниях это запрещено.
2. **Корпоративный сервер моделей** внутри вашей сети: данные остаются в контуре, а модель и железо выбирают администраторы. Если такого сервера пока нет, это следующий шаг.
3. **Модель на компьютере инженера**: когда облако запрещено, а корпоративного сервера ещё нет или он только настраивается. Данные не покидают компьютер, но модель слабее облачной и отвечает медленнее.

Дальше — о третьем варианте; настройка клиента для второго такая же, меняется только адрес сервера.

## Что умеет локальная модель {#capabilities}

Проверено на Mac с M4 Pro и 48 ГБ памяти, контекст 64 тыс. токенов, тестовый кластер из одного брокера и трёх топиков (7 партиций, около 3 тыс. сообщений). Три типичные задачи: проверка кластера с объяснением находок, лаг группы без участников и поиск сообщения по времени из лога сервиса. Каждую модель прогоняли по три раза.

| Модель (4 бита) | Сервер | Верных ответов | Генерация | Проверка кластера | Лаг группы | Поиск сообщения |
|---|---|---|---|---|---|---|
| Qwen3.6-35B-A3B | Ollama | 9 из 9 | 70–80 токенов/с | 23–29 с | 8–31 с | 34–43 с |
| Qwen3.6-35B-A3B | vllm-metal | 9 из 9 | 25–30 токенов/с | 33–52 с | 43–60 с | около 2 мин |
| Qwen3.8-27B | vllm-metal | 9 из 9 | 8–10 токенов/с | 8–16 мин | 10–12 мин | 28–46 мин |

Qwen3.8-27B отвечает подробнее, но это плотная модель: на каждый токен она задействует все 27 млрд параметров, а Qwen3.6-35B-A3B — около 3 млрд. Для повседневной работы на Mac подходит Qwen3.6-35B-A3B в Ollama: на нём та же модель отвечает в полтора-три раза быстрее, чем на vllm-metal.

Слабее облачной модели локальная справляется с длинными расследованиями из многих шагов: чаще ошибается в аргументах инструментов и может сделать неверный вывод из неполных данных. Проверяйте её выводы по журналу MCP.

## Железо и модели {#hardware}

Лучше всего на обычном железе работают модели MoE с малым числом активных параметров (около 3 млрд, например Qwen3.6-35B-A3B): они быстрее плотных моделей того же размера. Контекст нужен не меньше 32 тыс. токенов, лучше 64 тыс.

| Платформа | Сервер моделей | Что поместится |
|---|---|---|
| macOS, Apple Silicon, 48 ГБ и больше | vllm-metal или Ollama | Qwen3.6-35B-A3B (проверено) |
| macOS, Apple Silicon, 32 ГБ | Ollama | gpt-oss-20b; 35B-A3B — на пределе |
| Linux, NVIDIA 24 ГБ видеопамяти | vLLM | 35B-A3B в 4 битах с меньшим контекстом |
| Windows, NVIDIA | Ollama; vLLM — только в WSL2 | как в Linux |
| x86 без видеокарты, 32–64 ГБ DDR5 | Ollama | только модели MoE, медленно |

Mac с процессором Intel для локальных моделей не подходит.

## Сервер модели {#server}

Сервер должен отдавать OpenAI-совместимый API с вызовом инструментов. На Mac проще всего [Ollama](https://ollama.com): установите приложение, скачайте модель и создайте её вариант с контекстом 64 тыс. токенов — по умолчанию Ollama берёт контекст меньше, и описания инструментов Glafira в него не помещаются:

```bash
ollama pull qwen3.6:35b-a3b
printf 'FROM qwen3.6:35b-a3b\nPARAMETER num_ctx 65536\n' > Modelfile
ollama create qwen3.6-64k:35b-a3b -f Modelfile
```

Клиенту нужны адрес `http://127.0.0.1:11434/v1`, модель `qwen3.6-64k:35b-a3b` и любой непустой ключ API. Ollama слушает только `127.0.0.1`, поэтому с других компьютеров к модели не подключиться.

После 5 минут простоя Ollama выгружает модель из памяти, и следующий вопрос ждёт, пока она загрузится снова. Чтобы модель оставалась в памяти дольше, задайте переменную окружения `OLLAMA_KEEP_ALIVE`, например `1h`.

На Linux с NVIDIA обычно берут vLLM. Разбор вызовов инструментов у него задаёт флаг `--tool-call-parser` под семейство модели (для Qwen3.6 — `qwen3_coder`), у Ollama — шаблон модели.

## Клиенты {#clients}

Проверены два клиента для командной строки. В обоих отключите встроенные инструменты оболочки, правки файлов и веб-запросов: иначе модель может обойти Glafira и обратиться к кластеру или в интернет сама. Новый клиент Glafira покажет в диалоге подтверждения под его именем.

**Qwen Code** (открытый, Apache 2.0). Настройки — в `~/.qwen/settings.json`; создайте файл до первого запуска, иначе Qwen Code обновится и включит автоматическое одобрение действий:

```json
{
  "env": { "LOCAL_LLM_API_KEY": "ollama" },
  "modelProviders": { "openai": [ {
    "id": "qwen3.6-64k:35b-a3b",
    "envKey": "LOCAL_LLM_API_KEY",
    "baseUrl": "http://127.0.0.1:11434/v1",
    "generationConfig": { "contextWindowSize": 65536,
      "samplingParams": { "temperature": 0.2, "max_tokens": 8192 } } } ] },
  "security": { "auth": { "selectedType": "openai" } },
  "model": { "name": "qwen3.6-64k:35b-a3b" },
  "privacy": { "usageStatisticsEnabled": false },
  "general": { "enableAutoUpdate": false },
  "telemetry": { "enabled": false },
  "tools": { "approvalMode": "default",
    "disabled": ["run_shell_command", "edit", "write_file", "web_fetch", "web_search", "agent"] },
  "mcpServers": { "glafira-kafka": {
    "command": "/Applications/Glafira for Apache Kafka.app/Contents/MacOS/glafira-kafka",
    "args": ["mcp"], "timeout": 120000, "trust": true, "alwaysLoadTools": true } }
}
```

`envKey` — имя переменной с ключом, а не сам ключ. `alwaysLoadTools` отдаёт модели инструменты Glafira сразу, без лишнего шага поиска инструмента. В Glafira клиент называется `qwen-cli-mcp-client-glafira-kafka`. Если сервер описан в настройках папки (`.qwen/settings.json`), его нужно один раз одобрить командой `qwen mcp approve glafira-kafka`.

**Claude Code** работает с Ollama напрямую: Ollama отвечает и в формате Anthropic. Задайте переменные окружения и добавьте Glafira командой из блока [[ui:settings.mcp.connectTitle]]:

```bash
export ANTHROPIC_BASE_URL=http://127.0.0.1:11434
export ANTHROPIC_AUTH_TOKEN=ollama
export ANTHROPIC_MODEL=qwen3.6-64k:35b-a3b
export ANTHROPIC_DEFAULT_OPUS_MODEL=qwen3.6-64k:35b-a3b
export ANTHROPIC_DEFAULT_SONNET_MODEL=qwen3.6-64k:35b-a3b
export ANTHROPIC_DEFAULT_HAIKU_MODEL=qwen3.6-64k:35b-a3b
export CLAUDE_CODE_SUBAGENT_MODEL=qwen3.6-64k:35b-a3b
export CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC=1
claude --disallowedTools "Bash Edit Write WebFetch WebSearch Task"
```

`ANTHROPIC_BASE_URL` — без `/v1`. `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC` выключает обновления, телеметрию и отчёты об ошибках. Вход в учётную запись Anthropic не нужен. В Glafira клиент называется `claude-code`.

Оба клиента проверены на тех же трёх задачах, что и в [таблице выше](local-llm.md#capabilities), с моделью `qwen3.6-64k:35b-a3b` в Ollama, по три прогона:

| Клиент | Верных ответов | Проверка кластера | Лаг группы | Поиск сообщения |
|---|---|---|---|---|
| Qwen Code 0.26.5 | 9 из 9 | 30–98 с | 33–43 с | 66–108 с |
| Claude Code 2.1.316 | 9 из 9 | 43–59 с | 43–91 с | 74–98 с |

Оба клиента обращались только к инструментам Glafira. Без доступа в интернет, когда разрешены только соединения с `localhost`, они ответили так же. Claude Code иногда отвечает по-английски, даже если спросить по-русски: попросите его отвечать на вашем языке.

## Настройка Glafira {#glafira-settings}

В разделе [[ui:settings.mcp.section]]:

- [[ui:settings.mcp.responseLimit]] — наибольший ответ одного вызова инструмента. Ответ в 100 КБ занимает около 30 тыс. токенов, поэтому для контекста 64 тыс. выберите 48 или 24 КБ: Glafira обрежет длинные списки и подскажет модели сузить запрос.
- [[ui:settings.mcp.colCompact]] в списке [[ui:settings.mcp.clients]] — набор инструментов без заметок и предложений изменений: их описания занимают около 1 тыс. токенов контекста. Флажок появится, когда клиент подключится и вы его подтвердите; новый список клиент увидит после переподключения.

## Проверка {#check}

1. Подключите клиент и подтвердите его в диалоге Glafira.
2. Откройте ассистенту одно подключение, лучше тестовое, с уровнем [[ui:connections.form.llmLevel.metadata]].
3. Задайте три-четыре типичных вопроса: «Проверь кластер и объясни находки», «Почему у группы … большой лаг?», «Какие топики без репликации?».
4. В [[ui:settings.mcp.audit.title]] проверьте, какие инструменты вызывала модель и с каким результатом, и сверьте её ответ с данными в Glafira.
5. Если открываете сообщения, проверьте маскирование: кнопка [[ui:settings.mcp.audit.openInBrowse]] показывает те же сообщения без маскирования.
6. Отключите сеть и повторите один вопрос: ответ должен прийти без интернета.

## Ограничения {#limits}

- Локальная модель отвечает в несколько раз медленнее облачной, а плотные модели вроде Qwen3.8-27B на Mac — ещё медленнее (см. [таблицу](local-llm.md#capabilities)).
- Пока работает модель, компьютеру остаётся меньше памяти: на Mac с 48 ГБ модель на 35 млрд параметров занимает около 20 ГБ.
- Модель может ошибиться в выводе. Glafira не даёт ей ничего менять в кластере, но решения принимаете вы.
