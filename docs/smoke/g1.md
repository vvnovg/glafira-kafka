# Смоук G1 (MCP-шлюз «только чтение»)

Сборка: `pnpm tauri build` (release; для шима нужен установленный бандл) или `pnpm tauri dev` для пунктов без запуска шимом (Glafira уже запущена; фрагменты конфига указывают на путь запущенного бинаря). Локальная Kafka: `docker compose -f dev/docker-compose.yml up -d`.

1. «Настройки» → «LLM-ассистенты (MCP)»: выключатель «Разрешить MCP-сервер» выключен, статус «Сервер выключен». Включить → «Сервер работает»; в каталоге данных (macOS: `~/Library/Application Support/io.github.vvnovg.glafira.kafka/`) появился `mcp.json` (права `-rw-------`), рядом `mcp.sock` (при слишком длинном пути — `glafira-kafka-mcp-….sock` в `$TMPDIR`, адрес сокета написан в `mcp.json`).
2. Подключение dev-стенда: отметить «Доступ для LLM (только метаданные)», сохранить → в дереве значок `LLM`. Второе подключение оставить без флажка.
3. Claude Desktop (macOS): в блоке «Подключение клиента» у фрагмента «Claude Desktop: добавьте в claude_desktop_config.json» нажать «Копировать» → вставить в `~/Library/Application Support/Claude/claude_desktop_config.json` (запись `glafira-kafka` в `mcpServers`) → перезапустить Claude Desktop. В Glafira — диалог «claude-ai … хочет подключиться к Glafira», окно привлекает внимание (Dock). «Разрешить».
4. В Claude: «Какие подключения Kafka доступны?» → только подключение с флажком. «Проверь здоровье кластера dev» → вызовы `get_cluster_overview`, `list_topics`; индикатор `LLM: claude-ai` внизу боковой панели подсвечивается во время вызова.
5. Ребаланс: `docker exec -it ke-kafka kafka-console-consumer --bootstrap-server localhost:9092 --topic <топик> --group smoke-g1` в двух терминалах (топик должен существовать), один закрывать и открывать каждые ~10 с. В Claude: «Почему группа smoke-g1 постоянно ребалансируется?» → вызывается `observe_consumer_group` (окно по умолчанию 30 с, вызов длится немного дольше), ответ называет выходы и входы участников и хост.
6. Снять «Доступ для LLM (только метаданные)» у подключения (без переподключения клиента) → следующий вопрос о нём — ошибка `not_allowed`.
7. «Подтверждённые клиенты» → «Отозвать» у claude-ai → сессия закрылась (пропала из «Активные сессии»); переподключить Glafira в Claude (Claude Desktop — перезапустить; Claude Code — `/mcp`) → снова диалог. «Отклонить» → сессия закрывается, Claude получает отказ (обрыв соединения); при следующем подключении Glafira спрашивает снова, в «Подтверждённые клиенты» отказавший не появляется.
8. «Журнал MCP»: строки вызовов (время, клиент, инструмент или событие, подключение, результат, мс); «Показать файл» показывает `mcp-audit.jsonl` в Finder; в файле нет содержимого ответов.
9. Закрыть Glafira → `mcp.json` удалён, шим завершился (Claude показывает, что сервер отключился). Перезапустить сервер в Claude (Claude Desktop — перезапустить приложение; Claude Code — `/mcp`) → шим запускает Glafira (окно появляется), через несколько секунд ответ приходит.
10. Выключить «Разрешить MCP-сервер» в «Настройках» → клиенты отключены, `mcp.json` удалён, статус «Сервер выключен». Перезапустить сервер в Claude → в логе MCP клиента (Claude Desktop: `~/Library/Logs/Claude/mcp-server-glafira-kafka.log`) строка `glafira mcp: MCP is disabled in Glafira: turn it on in Settings → LLM assistants (MCP)`; Glafira при этом не запускается.
11. Claude Code: выполнить в терминале команду из фрагмента «Claude Code: выполните в терминале» (`claude mcp add glafira-kafka -- '<путь>' mcp`; путь в одинарных кавычках, если в нём пробелы) → `claude` → `/mcp` показывает glafira-kafka connected; вопрос о топиках работает.
12. Политика (macOS, профиль по `docs/admin.md`, `mcpEnabled = false`): выключатель недоступен, под ним «MCP отключён вашей организацией», статус «Отключено вашей организацией»; `…/Contents/MacOS/glafira-kafka mcp` в терминале → `glafira mcp: MCP is disabled by your organization`, код 1. Убрать политику.
13. Две копии Glafira (`open -n -a …`): во второй статус «MCP обслуживает другое окно Glafira».
14. Windows (release): то же для Claude Desktop (`%APPDATA%\Claude\claude_desktop_config.json`); проверить, что шим из GUI-бинаря отвечает (пункты 3–4) и что закрытие Claude Desktop не закрывает Glafira.
15. Linux AppImage: фрагмент «Другие stdio-клиенты: команда и аргументы» содержит путь к `.AppImage`; запуск шимом при закрытой Glafira поднимает её.
16. Экран группы smoke-g1: строка «Координатор: брокер 1 (localhost:9092) · протокол: classic»; для участника с `group.instance.id` (консьюмер с `--consumer-property group.instance.id=a`) — колонка `group.instance.id`.
17. F1 в разделе MCP — глава «LLM-ассистенты (MCP)»; F1 у выбора языка — «Начало работы». Глава на 12 языках: метки совпадают с интерфейсом.
