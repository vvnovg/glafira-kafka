# Смоук G2 (проверка кластера и замечания)

Сборка: `pnpm tauri dev` (пункты 1–9, 15–16) и release-бандл с MCP-клиентом для пунктов 10–14 (см. `docs/smoke/g1.md`, п. 3 и 11). Локальная Kafka: `docker compose -f dev/docker-compose.yml up -d` — один брокер, поэтому на prod сразу будут «Кластер из одного брокера» и «Фактор репликации 1».

Лицензия: для пунктов 1–10 нужна лицензия Pro (ключ — `docs/licensing.md`; перевод подключения в prod — функция Pro). Перед п. 11 ключ удалить («Лицензия» → «Удалить ключ» → «Да, удалить»), перед п. 12 — ввести снова.

Подготовка (в терминале):

```bash
docker exec ke-kafka kafka-topics --bootstrap-server localhost:9092 --create --topic smoke-g2 --partitions 1 --replication-factor 1
docker exec ke-kafka kafka-topics --bootstrap-server localhost:9092 --create --topic smoke-g2-isr --partitions 1 --replication-factor 1 --config min.insync.replicas=2
seq 1 3 | docker exec -i ke-kafka kafka-console-producer --bootstrap-server localhost:9092 --topic smoke-g2
docker exec ke-kafka kafka-consumer-groups --bootstrap-server localhost:9092 --group smoke-g2-empty --topic smoke-g2 --reset-offsets --to-earliest --execute
```

1. Подключение dev-стенда: в форме подключения окружение **prod**, сохранить. «Обзор кластера» → кнопка «Проверить кластер» → «Проверка…», затем строка «Последняя проверка: сейчас · в Glafira» (или «… 2 секунды назад · в Glafira» — время считается от начала проверки, строка сама не обновляется) и точки с числами по строгости.
2. Блок «Замечания» на обзоре: «Кластер из одного брокера» (критично). Ссылка «Все замечания» открывает вкладку «Замечания». Ссылка «Все замечания» есть и в строке «Последняя проверка» — даже когда блока нет.
3. Вкладка «Замечания»: группы «Фактор репликации 1» (`smoke-g2`, `smoke-g2-isr`, `__consumer_offsets` и другие), «min.insync.replicas больше фактора репликации» (`smoke-g2-isr`), «Брошенные группы» (`smoke-g2-empty`, «непрочитанных сообщений: 3»). У находки — пояснение и «Что делать:»; имя объекта открывает его вкладку.
4. Фильтры: «Строгость» → «Предупреждение» оставляет только предупреждения; «Объект» → «Группа»; поиск «isr» — только `smoke-g2-isr`; «Под фильтры ничего не подходит.» при пустом результате.
5. В дереве у пункта «Замечания» — точка с числом критичных и предупреждений. У `smoke-g2` нажать «Скрыть для этого объекта» → находка пропала, число в значке уменьшилось; «Показать скрытые (1)» → находка видна с кнопкой «Вернуть»; «Вернуть» — снова в списке.
6. «Топики»: в последней колонке (●) у `smoke-g2-isr` — точка с числом; экран топика `smoke-g2-isr` — блок «Замечания» с двумя находками. Наведите указатель на точку: в подсказке — «Требуют внимания: N» и заголовки находок построчно (не больше 10, дальше «…»). «Consumer groups»: точка у `smoke-g2-empty`, на экране группы — блок с «Группа smoke-g2-empty пуста, но у неё есть лаг».
7. Окружение подключения **dev**, сохранить, «Проверить кластер»: «Кластер из одного брокера» и «Фактор репликации 1» пропали, «min.insync.replicas больше фактора репликации» — предупреждение, «Брошенные группы» — информация.
8. Рост лага: подождать больше минуты после проверки, затем `seq 1 3000 | docker exec -i ke-kafka kafka-console-producer --bootstrap-server localhost:9092 --topic smoke-g2` и «Проверить кластер» → «Лаг группы smoke-g2-empty растёт» («Лаг вырос с 3 до 3003 с проверки … мин назад»).
9. Без связи с кластером (`docker stop ke-kafka`) «Проверить кластер» → баннер ошибки с «Повторить»; прошлая проверка и её находки остались. `docker start ke-kafka`.
10. MCP (Claude Code или Claude Desktop, клиент подтверждён, у подключения «Доступ для LLM (только метаданные)»). Не раньше чем через 5 минут после проверки п. 8 — иначе `health_check` вернёт её же и в строке останется «· в Glafira»; или попросите свежую проверку (клиент передаёт `maxAgeSeconds: 0`). «Проверь здоровье кластера dev» → вызов `health_check`; ответ называет находки; в Glafira «Последняя проверка: … · claude-code» (или `claude-ai`). Повторный вопрос в течение 5 минут — без новой проверки (время в строке не меняется).
11. Free (без лицензии): «Оставь замечание по топику smoke-g2-isr» → клиент получает `pro_required`, ассистент сообщает, что нужен Pro. В разделе «Замечания LLM» — «🔒 Pro» и текст про Glafira Pro. Экран «Лицензия» → «Что даёт Pro»: третьим пунктом — «Замечания LLM…».
12. Pro (лицензия): та же просьба → замечание сразу появляется на вкладке и в блоке топика: заголовок, текст как есть (переводы строк сохранены, ссылки не кликабельны), «Замечание LLM · claude-code». «Решено» → «Закрытые (1)»; спросить ассистента «какие замечания закрыты?» → `list_annotations` видит `resolved`. Попросить ассистента удалить своё замечание → `remove_annotation`, замечание пропало.
13. Попросить ассистента оставить ещё два замечания (по топику `smoke-g2` и по группе `smoke-g2-empty`). «Удалить все замечания LLM» → вопрос на странице «Удалить все замечания LLM у этого подключения?» → подтвердить → «Замечаний LLM нет.».
14. Перед перезапуском: у находки «min.insync.replicas больше фактора репликации» (`smoke-g2-isr`, на dev она есть — п. 7) нажать «Скрыть для этого объекта» и попросить ассистента снова оставить замечание по топику `smoke-g2-isr`. Перезапуск Glafira: последняя проверка, скрытая находка («Показать скрытые (1)») и замечание на месте. Файл `~/Library/Application Support/io.github.vvnovg.glafira.kafka/health/<id>.json` (`-rw-------`, каталог `drwx------`).
15. F1 на вкладке «Замечания» — глава «Проверка кластера и замечания»; переключение языка (12 языков) — метки главы совпадают с интерфейсом, тексты правил переведены.
16. Удалить подключение → файл `health/<id>.json` удалён.

Уборка:

```bash
docker exec ke-kafka kafka-consumer-groups --bootstrap-server localhost:9092 --delete --group smoke-g2-empty
docker exec ke-kafka kafka-topics --bootstrap-server localhost:9092 --delete --topic smoke-g2
docker exec ke-kafka kafka-topics --bootstrap-server localhost:9092 --delete --topic smoke-g2-isr
```
