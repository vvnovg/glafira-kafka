# Смоук G4 (чтение сообщений через MCP)

Сборка: `pnpm tauri dev` (Glafira запущена заранее; MCP-клиент — Claude Code из `~`, как в `docs/smoke/g1.md`, п. 11; клиент подтверждён). Локальная Kafka: `docker compose -f dev/docker-compose.yml up -d` — один брокер, контейнер `ke-kafka`. Во всех запросах к ассистенту называйте подключение («в подключении Local …») и свой часовой пояс («время — UTC+3»). Окно в вопросах — последний час; если смоук затянулся, называйте окно от времени подготовки.

Подготовка (в терминале):

```bash
docker exec ke-kafka kafka-topics --bootstrap-server localhost:9092 --create --topic smoke-g4 --partitions 2 --replication-factor 1
printf '%s\n' 'k1|{"orderId":123,"email":"ann@example.com","note":"card 4111 1111 1111 1111"}' 'k2|{"orderId":124,"email":"bob@example.com","status":"FAILED"}' 'k1|{"orderId":125,"password":"hunter2"}' | docker exec -i ke-kafka kafka-console-producer --bootstrap-server localhost:9092 --topic smoke-g4 --property parse.key=true --property key.separator='|'
```

1. Уровень доступа. Открыть форму подключения dev-стенда: вместо флажка — группа «Доступ для LLM» с «Нет», «Только метаданные», «Метаданные и сообщения» и подсказкой «?». Выбрать «Метаданные и сообщения»: ниже появился блок «Маскирование» с отмеченным «Стандартный список», списком имён (`*password*, passwd, …`) и пояснением «Email, номера карт, JWT и Bearer-токены маскируются всегда…». Сменить окружение на **prod** — под группой предупреждение «Содержимое сообщений этого production-кластера будет уходить провайдеру LLM»; вернуть **dev** и сохранить. В дереве значок `LLM` у подключения закрашен, подсказка при наведении — «Доступ для LLM: метаданные и сообщения». В «Настройках» → «LLM-ассистенты (MCP)» под статусом строка «Открыто для LLM: N, из них с сообщениями: 1».
2. Диалог подтверждения. В «Подтверждённых клиентах» нажать «Отозвать» у `claude-code`, в Claude Code выполнить `/mcp` и переподключить `glafira-kafka`: в диалоге после «Он увидит метаданные подключений…» строка «Содержимое сообщений он сможет читать в 1 из них.» и «Через Glafira ассистент может только читать: изменить что-либо в кластерах он не может. Пароли не передаются.» «Разрешить».
3. Обзор и чтение. «Что писалось в топик smoke-g4 за последний час? Время — UTC+3» (настаивать на вызове `summarize_messages`, затем `read_messages`) → вызовы `summarize_messages` (3 сообщения, ключ `k1` — 2 раза) и `read_messages`. В ответе ассистента и в выводе инструмента (раскрыть вызов в Claude Code) нет `ann@example.com`, `bob@example.com`, `hunter2` и номера карты: вместо них `"email":"***"`, `"password":"***"`, `card [card]` (в выводе Claude Code JSON сообщения — строка, поэтому кавычки экранированы: `\"email\":\"***\"`); `timeZone.utcOffset` — сдвиг этой машины.
4. Время без зоны. «Покажи сообщения smoke-g4 с 14:00 до 14:10» (без зоны): ассистент спрашивает часовой пояс или, если всё же вызовет `read_messages`, получает `invalid_argument` «timestamp has no time zone…» и переспрашивает.
5. Поиск по значению из лога. «Найди в smoke-g4 сообщение клиента bob@example.com за последний час» → `read_messages` с фильтром `value` по `bob@example.com`, найдено одно сообщение (`orderId` 124), email в ответе — `***`.
6. История коммитов. В терминале прочитать топик группой (консольный консьюмер коммитит сам):

   ```bash
   docker exec ke-kafka kafka-console-consumer --bootstrap-server localhost:9092 --topic smoke-g4 --group smoke-g4 --from-beginning --timeout-ms 8000
   ```

   «Что успела обработать группа smoke-g4 за последний час?» → `get_group_commit_history`: по партициям `smoke-g4` — `runs` с оффсетами и временем, `offsetsTopicPartition` — число. Затем «Покажи сообщения партиции 1, которые группа обработала» (оба ключа, `k1` и `k2`, попадают в партицию 1, партиция 0 пуста) → `read_messages` в режиме оффсетов (`partition` 1, `startOffset` 0, `endOffset` 3, то есть оффсеты 0–2) — три сообщения. Подсказка о праве Read на `__consumer_offsets` не проверяется на dev-стенде (нет ACL), покрыто автотестом.
7. Журнал и «Открыть в „Сообщениях“». В «Настройках» → «Журнал MCP» у строк `read_messages` и `summarize_messages` в колонке «Подробности» — «smoke-g4: N из M, замаскировано: K» и кнопка «Открыть в „Сообщениях“»; у `get_group_commit_history` — «smoke-g4: …» без кнопки. Ожидаемые числа (выведены из кода — проверить): у `read_messages` из п. 3 — «smoke-g4: 3 из 3, замаскировано: 4» (email дважды, номер карты, пароль); у `summarize_messages` — «smoke-g4: 61 из 3, замаскировано: 0», где первое число — корзины обзора, а не сообщения (около 60; 61 — за ровно час при шаге по умолчанию). Если в п. 3 ассистент не вызвал `read_messages`, повторить п. 3, настаивая на вызове. Нажать кнопку у `read_messages` из п. 3 → вкладка топика `smoke-g4`, подвкладка «Сообщения»: начальная позиция «С времени», заполнены «Время с» и «Время по» (границы округлены до секунды); чтение не началось. «Читать» → те же сообщения без маскирования (видны email и пароль). У строки из п. 5 после «Читать» — одно сообщение, в поле «Значение содержит» `bob@example.com`. Усечённые аргументы: в терминале `printf 'x%.0s' {1..1100} | pbcopy`, попросить «Найди в smoke-g4 за последний час сообщения, значение которых содержит <вставить строку>» (настаивать на вызове `read_messages`) → у новой строки «0 из 3, замаскировано: 0» без `smoke-g4:` (аргументы длиннее 1 КБ журнал усекает, цели в них не найти), кнопка «Открыть в „Сообщениях“» неактивна, подсказка при наведении — «Недоступно: аргументы вызова в журнале усечены».
8. Пометки о неточном переносе. У строки `read_messages` из п. 6 (режим оффсетов, без фильтра) нажать «Открыть в „Сообщениях“» → начальная позиция «С оффсета», оффсет 0, в поле партиций 1, «Лимит» 3 (`endOffset` − `startOffset`); пометок под формой нет. Попросить «Покажи сообщения smoke-g4 из партиции 1 с оффсета 0 до 3, не включая 3, только со статусом FAILED» (настаивать на вызове `read_messages` с `endOffset`) → «Открыть в „Сообщениях“» у новой строки: под формой «Лимит перенесён неточно: в форме он считает найденные сообщения, а не оффсеты, поэтому чтение может зайти за конечный оффсет вызова». Попросить «Найди в smoke-g4 за последний час сообщения с ключом по regex `k[12]` и значением, содержащим FAILED, без regex» (настаивать на вызове `read_messages`) → «Открыть в „Сообщениях“» у новой строки: под формой «Фильтры перенесены неточно: в форме флаги regex и регистра общие для ключа, значения и значения заголовка», флажок regex снят (флаги взяты у фильтра значения).
9. Свой список масок. В форме подключения снять «Стандартный список»: открылось поле со стандартными именами по одному на строку. Дописать строку из 65 букв `a` (`printf 'a%.0s' {1..65} | pbcopy`) и сохранить → ошибка «Имя поля для маскирования длиннее 64 символов: …»; убрать эту строку. Заменить содержимое поля на `orderId`, сохранить. Повторить вопрос п. 3: `"orderId":"***"`, а email и пароль — по шаблонам: email — `[email]`, `password` больше не в списке и виден как есть (это ожидаемо: свой список заменяет стандартный). В блоке «Журнал MCP» у новой строки `read_messages` — «smoke-g4: 3 из 3, замаскировано: 6» (`orderId` трижды, email дважды, номер карты; выведено из кода — проверить). Список пока не возвращать: он нужен в п. 10.
10. Экспорт и импорт. Пока у подключения «Метаданные и сообщения» и список `orderId`, в меню дерева подключений «Экспортировать всё…» и сохранить файл: в файле у подключения нет `llmAccess` и `llmMaskFields`. Переименовать подключение (например, дописать к имени `-2`), сохранить, затем в меню дерева «Импортировать…» этот файл с отмеченным «Обновлять существующие подключения»: подключение — в группе «Обновятся»; «Импортировать» → имя прежнее, а уровень «Метаданные и сообщения» и список `orderId` не изменились. Необязательно (удаление стирает историю отправки, шаблоны, замечания и предложения LLM подключения): удалить подключение — в блоке «Журнал MCP» кнопка у его строк `read_messages` неактивна, подсказка «Недоступно: подключения больше нет»; дописать в файл у подключения `"llmAccess": "messages",` (например, после строки с `"id"`) и импортировать его → подключение вернулось с уровнем «Нет»; выставить «Метаданные и сообщения». Вернуть «Стандартный список», сохранить.
11. Уровень на лету. Выбрать «Только метаданные», сохранить (MCP не переподключать). Попросить ещё раз прочитать smoke-g4 → ответ инструмента `messages_not_allowed: LLM access to this connection is limited to metadata…`, ассистент просит переключить уровень в Glafira. Значок `LLM` в дереве не закрашен. В блоке «Журнал MCP» кнопка «Открыть в „Сообщениях“» у строк `read_messages` из п. 3 неактивна, подсказка при наведении — «Недоступно: у подключения уровень не „Метаданные и сообщения“». Вернуть «Метаданные и сообщения» — кнопка снова активна.
12. Политика (macOS). Выйти из Glafira, затем:

    ```bash
    rm -f /tmp/policy.plist && plutil -create xml1 /tmp/policy.plist && plutil -insert mcpMessagesEnabled -bool NO /tmp/policy.plist
    sudo mkdir -p "/Library/Managed Preferences" && sudo cp /tmp/policy.plist "/Library/Managed Preferences/io.github.vvnovg.glafira.kafka.plist"
    sudo chmod 644 "/Library/Managed Preferences/io.github.vvnovg.glafira.kafka.plist"
    plutil -p "/Library/Managed Preferences/io.github.vvnovg.glafira.kafka.plist"   # mcpMessagesEnabled => false
    ```

    Запустить `pnpm tauri dev`. В форме подключения «Метаданные и сообщения» отмечен, но неактивен, рядом «Действует как „Только метаданные“: чтение сообщений отключено вашей организацией»; блока «Маскирование» нет. В форме нового подключения тот же переключатель неактивен с пометкой «Сообщения: отключено вашей организацией». Значок `LLM` в дереве не закрашен. В «Настройках» строка «Чтение сообщений отключено вашей организацией», счётчик «…из них с сообщениями: 0»; в блоке «Журнал MCP» кнопка у строк `read_messages` из п. 3 неактивна, подсказка «Недоступно: чтение сообщений отключено вашей организацией». Если ассистент не видит `glafira-kafka` после перезапуска Glafira — `/mcp` и переподключить. Запрос ассистенту прочитать smoke-g4 → `messages_disabled: Reading messages is disabled by the organization's policy`; метаданные (`describe_topic`) работают. В «О программе» ошибок политики нет. Неудачные вызовы (`invalid_argument` из п. 4, если он был, `messages_not_allowed` из п. 11, `messages_disabled`) в блоке «Журнал MCP» — с кодом в колонке «Результат», без подробностей и без кнопки; так и должно быть. Убрать политику: `sudo rm "/Library/Managed Preferences/io.github.vvnovg.glafira.kafka.plist"`, перезапустить Glafira.
13. Справка и языки. F1 в разделе MCP «Настроек» — глава «LLM-ассистенты (MCP)», раздел «Чтение сообщений» (после «Что видит ассистент»); в «Включение» шаг 3 про уровни. Переключить язык на любой другой: переключатели уровня, блок «Маскирование», подсказки «?» и строка журнала переведены; вернуть язык.
14. Файл журнала. «Показать файл» → в `mcp-audit.jsonl` у строк `read_messages` есть `scanned`, `returned`, `masked` и `args` с окном и фильтром; содержимого сообщений (email, `orderId`) в файле нет, кроме значений фильтров в `args` (п. 5, 7, 8).

Уборка:

В Glafira: у подключения уровень «Метаданные и сообщения» или прежний, «Стандартный список» отмечен.

```bash
docker exec ke-kafka kafka-consumer-groups --bootstrap-server localhost:9092 --delete --group smoke-g4
docker exec ke-kafka kafka-topics --bootstrap-server localhost:9092 --delete --topic smoke-g4
rm -f /tmp/policy.plist
ls "/Library/Managed Preferences/io.github.vvnovg.glafira.kafka.plist"   # No such file or directory
```
