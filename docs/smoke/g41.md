# Смоук G4.1 (хвосты G4)

Сборка: `pnpm tauri dev` из ветки `feature/g41-g4-tails` (Glafira запущена заранее). MCP-клиент — Claude Code из `~`, клиент подтверждён, как в `docs/smoke/g4.md`. Стенд — тот же: `docker compose -f dev/docker-compose.yml up -d`, топик `smoke-g4` из подготовки смоука G4 (если его нет — создать командами оттуда). У подключения dev-стенда уровень «Метаданные и сообщения» и стандартный список масок. Во всех запросах к ассистенту называйте подключение и свой часовой пояс («время — UTC+3»).

Подготовка (в терминале):

```bash
printf '%s\n' 'k3|Cookie: a=1; sessionid=xyz' | docker exec -i ke-kafka kafka-console-producer --bootstrap-server localhost:9092 --topic smoke-g4 --property parse.key=true --property key.separator='|'
```

1. Куки до конца строки. «Покажи сообщения с ключом k3 в smoke-g4 за последний час. Время — UTC+3» (настаивать на вызове `read_messages`) → `read_messages` с фильтром по ключу `k3`; значение сообщения — `Cookie: ***`, `sessionid` и `xyz` не видны ни в ответе ассистента, ни в выводе инструмента (раскрыть вызов в Claude Code). В «Настройках» → «Журнал MCP» у этой строки — «smoke-g4: 1 из N, замаскировано: 1» (N — все сообщения топика в окне).
2. Топик без права Describe. На dev-стенде ACL нет, поэтому шаг не выполняется. Путь MCP — `read_messages`, `summarize_messages` и `get_group_commit_history` — проверяют тесты `topic_without_describe_is_not_authorized_and_a_missing_one_is_not_found` и `offsets_topic_without_describe_is_not_authorized` (фальшивый брокер с ответом `TOPIC_AUTHORIZATION_FAILED`): вместо «не найден» у `read_messages` и `summarize_messages` — `NOT_AUTHORIZED: Not authorized to perform the operation`, у `get_group_commit_history` к тому же тексту дописано «. Reading __consumer_offsets requires the Read permission on this internal topic». Экран «Сообщения» отдельного теста не имеет: он использует ту же `topic_partitions`, и вместо «не найден» там «Недостаточно прав для операции».
3. Предупреждение о prod для программы чтения экрана. Открыть форму подключения dev-стенда. Включить VoiceOver (Cmd+F5). Если уровень не «Метаданные и сообщения», выбрать его. Сменить «Окружение» на **prod** → VoiceOver произносит «Содержимое сообщений этого production-кластера будет уходить провайдеру LLM» (раньше молчал). Вернуть **dev**, форму не сохранять (закрыть вкладку). Выключить VoiceOver (Cmd+F5).
4. Значки LLM. Нужно второе подключение, кроме dev-стенда (если его нет — создать любое, например с тем же адресом `localhost:9092`): у него будет контурный значок, у dev-стенда — закрашенный.
   1. Открыть форму второго подключения, запомнить его уровень доступа для LLM, выставить «Только метаданные» и сохранить.
   2. Включить VoiceOver (Cmd+F5). Перейти в дереве подключений к значку `LLM` у подключения dev-стенда (VO+стрелки: Ctrl+Option+→) → VoiceOver читает «Доступ для LLM: метаданные и сообщения», а не просто «LLM».
   3. Перейти к значку `LLM` у второго подключения → VoiceOver читает «Открыто LLM-ассистентам по MCP». Выключить VoiceOver (Cmd+F5).
   4. В «Системных настройках» → «Оформление» переключить светлую и тёмную тему: в обеих текст обоих значков читается чётко (закрашенный — белый на синем, контурный — синий).
   5. Вернуть второму подключению прежний уровень и сохранить (или удалить подключение, если оно создано для смоука).
5. Скрытый список масок не мешает сохранению. В форме подключения при уровне «Метаданные и сообщения» снять «Стандартный список» и дописать в поле строку из 65 букв `a` (`printf 'a%.0s' {1..65} | pbcopy`, вставить новой строкой). Выбрать уровень «Только метаданные» (блок «Маскирование» скрылся) → «Сохранить» → сохранено без ошибки. Снова открыть форму, выбрать «Метаданные и сообщения» → в поле видна строка из 65 букв; «Сохранить» → ошибка «Имя поля для маскирования длиннее 64 символов: …». Убрать эту строку, отметить «Стандартный список», сохранить.

Уборка: в «Журнале MCP» ничего чистить не нужно; топик `smoke-g4` лучше удалить: лишнее сообщение `k3` изменило бы точные числа («3 из 3», «1 из 3») при следующем прогоне `docs/smoke/g4.md` (`docker exec ke-kafka kafka-topics --bootstrap-server localhost:9092 --delete --topic smoke-g4`).
