# Смоук M3b (dev-сборка, macOS)

> Примечание (0.3.0): лицензионных ключей и экрана «Лицензия» больше нет, все функции бесплатны; шаги про Pro/Free и лицензию устарели.

Запуск: `docker compose -f dev/docker-compose.yml up -d`, затем `pnpm tauri dev`.
Окно называется «Glafira for Apache Kafka».

## Переименование и миграция
1. В дереве — все прежние подключения (Local, Prod, mtls и т. п.), шаблоны в Producer, история отправки.
   Открыть «Топики» у подключения с паролем (SASL или mTLS с паролем ключа) — подключается без повторного ввода пароля.
   (При первом запуске macOS может спросить доступ к старым записям keychain «kafka-explorer» — разрешить.)
2. Старые данные не тронуты: `ls ~/Library/Application\ Support/dev.kafkaexplorer.app` — файлы на месте.

## Логи и «О программе»
3. Внизу дерева — «О программе». Видны версия `0.2.0`, сборка (короткий хэш коммита), система, «Политика организации: нет»,
   пути «Данные» и «Логи».
4. `tail ~/Library/Logs/io.github.vvnovg.glafira.kafka/app.log` — строки `запуск`, `политика`; паролей и ключей в логе нет
   (`grep -iE "password|PRIVATE KEY|admin-secret|keypass" ~/Library/Logs/io.github.vvnovg.glafira.kafka/app.log` — пусто).
5. «Собрать диагностику» → сохранить zip → «Архив сохранён: …». В архиве `info.json`, `connections.json`, `logs/app.log`; паролей нет.
   Повторно «Собрать диагностику» и нажать «Отмена» в диалоге — ничего не происходит, прошлое сообщение остаётся.

## Обновления
6. «Проверить обновления» → «Обновления не настроены в этой сборке» (ключ updater ещё не задан) — без сетевой ошибки.
7. Политика `updatesEnabled = false` (как в смоуке M3a п. 11, но путь `/Library/Managed Preferences/io.github.vvnovg.glafira.kafka.plist`)
   → перезапуск → «Проверить обновления» → «Обновления управляются вашей организацией». Удалить файл политики после проверки.
