# Glafira for Apache Kafka — папки подключений, экспорт и импорт

**Дата:** 2026-10-17
**Зачем:** у разработчиков и тестировщиков десятки подключений к стендам (dev, ИФТ, ПТ, ПСИ, prod) нескольких систем.
Их нужно раскладывать по папкам и переносить между компьютерами одним файлом.

## 1. Решения

| Вопрос | Решение |
|---|---|
| Структура | Вложенные папки любой глубины; папка — отдельная сущность |
| Окружение | Поле «окружение» (local/dev/test/stage/prod) остаётся как есть — цвет и защита prod; папки от него не зависят |
| Пароли при экспорте | Не экспортируются; в файле — флаги «нужен пароль», после импорта получатель вводит свои |
| Импорт | Слияние с предпросмотром; цель — корень или выбранная папка |
| Экспорт | Всё дерево или выбранная папка |
| Тариф | Папки, экспорт и импорт — во Free. prod-подключение из файла во Free импортируется с `readOnly: true`; снять read-only можно только с Pro (`save_connection` требует Pro, если prod-профиль переходит из read-only в запись, как и при переводе в prod). Остальные поля read-only prod-профиля во Free редактируются; уже доступный для записи prod-профиль (например, со времён Pro) остаётся редактируемым |
| Совместимость | Версия формата — мажор; новые поля и значения её не повышают; неизвестные поля игнорируются; ошибка — только при мажоре больше поддерживаемого |

## 2. Модель данных

`src-tauri/src/storage/connections.rs`, файл `connections.json`:
- папка `ConnectionFolder { id: String (UUID), name: String, parent_id: Option<String>, order: i64 }`;
- у `ConnectionProfile` — `folder_id: Option<String>` и `order: i64` (`#[serde(default)]`);
- в `ConnectionsFile` — `folders: Vec<ConnectionFolder>` (`#[serde(default)]`).

**Версия схемы** остаётся `1`: изменения добавочные. Неизвестные поля файла сохраняются при записи
(`#[serde(flatten)] extra: serde_json::Map` в `ConnectionsFile`, `ConnectionProfile`, `ConnectionFolder`), чтобы файл из более новой
Glafira не терял данные. Ошибка чтения — только при `schema_version` больше поддерживаемой (как сейчас).
Папки и подключения читаются по одному: запись, которую эта версия не может разобрать (новое окружение, протокол, механизм
аутентификации и т. п.), не ломает файл. Она хранится как есть (`raw_connections` / `raw_folders` в `StoreData`), в приложении
не показывается, `check_tree` её не учитывает, ссылки на нечитаемую папку считаются корнем; при записи такие записи возвращаются
в конец своих списков без изменений, в журнал пишется предупреждение (номер и id записи, без значений полей).
Откат на 0.2.x: подключения сохраняются, раскладка по папкам теряется при первой записи старой версией.

**Инварианты** (проверяет Rust при каждой операции):
- `parent_id` и `folder_id` ссылаются на существующие папки (иначе — корень при чтении, ошибка при записи);
- нет циклов: папку нельзя переместить в неё саму или в её потомка;
- имя папки непустое, до 100 символов; имена папок внутри одного родителя уникальны (без учёта регистра);
- удалить можно только пустую папку.

**Сохранение подключения:** `save_connection` существующего подключения не меняет его папку и порядок — их меняют только команды перемещения (форма вызывает `moveItems`).
Неизвестные поля профиля из запроса `save_connection` не принимаются: существующий профиль сохраняет свои (как в файле),
новый получает пустые. Их пишет в файл только сама Glafira, поэтому имена неизвестных полей не проверяются
(поле `passwordRotationDays` из более новой версии не мешает сохранению); на секреты проверяются только дополнительные свойства
librdkafka (`extraProperties`), которые вводит пользователь.

**Миграция:** существующие подключения — в корне, `order` — по текущему порядку списка.

## 3. Команды Rust

| Команда | Что делает |
|---|---|
| `list_folders() -> Vec<ConnectionFolder>` | все папки; профили из `list_connections` несут `folderId` и `order`, дерево собирает фронтенд |
| `create_folder(name, parent_id) -> ConnectionFolder` | новая папка в конце уровня |
| `rename_folder(id, name)` | переименование |
| `delete_folder(id)` | только пустую, иначе `AppError` `errors.folders.notEmpty` |
| `move_items(items: [{ kind: "folder" \| "connection", id }], parent_id, before_id?)` | перемещение и порядок; запрет циклов — `errors.folders.cycle` |
| `export_connections(path, folder_id?) -> { connections, folders }` | файл формата §4; без секретов |
| `preview_import(path, target_folder_id?, update_existing) -> ImportPreview` | разбор и план без записи |
| `apply_import(path, target_folder_id?, update_existing) -> ImportResult` | применение одной записью файла; при ошибке не меняется ничего |

Поле «Папка» в форме применяется через `move_items` (см. §2). Все тексты ошибок — ключи словарей (`errors.folders.*`, `errors.import.*`).

## 4. Формат файла экспорта

Расширение `.glafira-connections.json`:

```json
{
  "format": "glafira-connections",
  "version": 1,
  "exportedAt": "2026-10-17T12:00:00Z",
  "appVersion": "0.3.0",
  "folders": [{ "id": "…", "name": "ИФТ", "parentId": null, "order": 0 }],
  "connections": [{ "…профиль без секретов…": "", "folderId": "…", "order": 0, "needsPassword": { "sasl": true, "truststore": false, "keystore": false, "key": false } }]
}
```

- При экспорте папки корнем становится она сама (`parentId: null`); подключения вне поддерева не попадают.
- Секреты не пишутся никогда; `needsPassword` — какие пароли у подключения были сохранены.
- Пути к сертификатам — как есть.
- **Совместимость при чтении:** `format` должен совпасть; `version` больше поддерживаемой (1) — ошибка
  `errors.import.incompatibleVersion` («Файл создан в несовместимой версии Glafira — обновите приложение»);
  неизвестные поля игнорируются; подключение с неизвестным значением (например, новый механизм аутентификации) или не прошедшее
  валидацию профиля пропускается с причиной в предпросмотре, остальные импортируются.

## 5. Правила импорта

- Сопоставление подключений и папок — по `id`.
- **Новые** папки и подключения создаются под целью (корень или выбранная папка) с той же структурой, что в файле.
- **Совпавшие подключения** при `update_existing = true` получают настройки из файла, но остаются в своей папке и сохраняют пароли
  получателя; при `false` — не меняются. «Без изменений» — если настройки совпадают.
- **Совпавшие папки** не перемещаются и не переименовываются; новое добавляется внутрь них.
- Конфликт имени: новая папка или подключение с именем, уже занятым в той же папке, получает суффикс « (2)», « (3)»…
- Подключения получателя, которых нет в файле, не трогаются.
- **Free:** подключение с `environment = prod` (новое или обновлённое) получает `readOnly: true`; предупреждение в предпросмотре.
- После применения — сообщение «Импортировано: добавлено N, обновлено M; введите пароли для K подключений».

`ImportPreview`: `{ added: [{ kind, id, name, path }], updated: [...], unchanged: [...], skipped: [{ name, reason: LocalizedText }],
warnings: [{ key, params }] }`; предупреждения: prod во Free, отсутствующие файлы сертификатов на этом компьютере, нужны пароли.

## 6. Интерфейс

**Левая панель:**
- дерево: папки (сворачиваются, состояние — в `localStorage`), внутри — папки и подключения по `order`, папки первыми;
  у подключения по-прежнему раскрываются «Топики», «Группы» и т. д.;
- поле фильтра над деревом: остаются ветки с совпадением по имени папки или подключения;
- заголовок панели: «+ подключение», «+ папка», меню «⋯» — «Экспортировать всё…», «Импортировать…»;
- у папки — контекстное меню (правый клик и кнопка «⋯»): «Новая папка», «Новое подключение здесь», «Переименовать»,
  «Удалить», «Экспортировать папку…», «Импортировать сюда…»;
- перетаскивание папок и подключений между папками и внутри уровня (HTML5 drag-and-drop); недопустимая цель не подсвечивается.

**Форма подключения:** поле «Папка» — выпадающий список путей («Проект А / ИФТ»), по умолчанию — папка, из которой создавали.

**Диалог импорта:** цель (выпадающий список путей, при «Импортировать сюда» выбрана), флажок «Обновлять существующие» (включён),
сводка, раскрываемый список «новое / обновится / без изменений / пропущено», предупреждения, кнопки «Импортировать» и «Отмена».
Подсказки «?» — у цели и у флажка.

Все строки — через словари на 8 языках (en, ru, de, fr, es, it, pl, pt-BR), по глоссарию; новые термины (папка, экспорт, импорт)
вносятся в глоссарий.

## 7. Тесты

- **Rust:** миграция (подключения в корне, порядок сохранён); сохранение неизвестных полей; операции с папками, циклы, удаление
  непустой; экспорт всего и поддерева без секретов, `needsPassword`; предпросмотр и применение по каждому правилу §5, включая цель,
  `update_existing = false`, конфликт имён, prod во Free, пропуск неизвестного значения, лишние поля, мажор больше поддерживаемого,
  атомарность (ошибка записи — файл не изменён).
- **Фронтенд:** дерево, сворачивание, фильтр, меню папки, перетаскивание (логика `move_items` вызывается с правильными аргументами),
  поле «Папка», диалог импорта (сводка, цель, флажок, предупреждения).
- **Смоук `docs/smoke/folders.md`:** папки и перетаскивание; экспорт всего и папки; импорт на «чистом» профиле, повторный импорт
  с изменениями, импорт в выбранную папку; Free и prod; файл с лишними полями.

## 8. Вне объёма

Экспорт с паролями (в том числе зашифрованный); раздача файла подключений политикой организации; синхронизация через облако;
импорт из других клиентов (Offset Explorer, Conduktor); мультивыбор в дереве.
