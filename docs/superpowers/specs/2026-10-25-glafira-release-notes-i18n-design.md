# Заметки к обновлению на языке интерфейса — дизайн

Дата: 2026-10-25. Формат согласован с владельцем (вариант A).

## Проблема
«О программе» → «Обновления» показывает `notes` из `latest.json` моноширинным блоком `<pre>`. `notes` — раздел
`## X.Y.Z` русского `CHANGELOG.md`, поэтому на любом языке интерфейса заметки русские и в виде сырого Markdown.

## Решение
1. **Источники.** `CHANGELOG.md` — английский, основной (как README). Остальные языки интерфейса —
   `docs/changelog/<код>.md` с теми же разделами `## X.Y.Z`. Русский — бывший `CHANGELOG.md` целиком, английский —
   перевод всей истории, остальные 10 языков начинаются с 0.5.0. Набор языков — `src/i18n/languages.ts`.
2. **`latest.json`.** `notes` — английский раздел (его показывают версии до 0.5.0 включительно, как есть);
   новое поле `notes_i18n` — `{ код: раздел }` для всех языков, где раздел есть. tauri-plugin-updater 2.x не знает
   этого поля и пропускает его (разбор без `deny_unknown_fields`), а весь ответ сервера отдаёт как `Update::raw_json`.
3. **Тело GitHub-релиза** — английский раздел (тот же текст, что `notes`).
4. **Скрипты.** `scripts/changelog.mjs` — путь файла языка и разбор раздела (один разбор для всех скриптов, awk из
   `release.yml` убран). `make-latest-json.mjs` читает разделы сам и пишет английский в `--notes-out` для тела релиза.
   `check-release.mjs`: нет английского раздела — ошибка; нет раздела на другом языке — ошибка при сборке по тегу,
   предупреждение в пробном прогоне. `pnpm i18n:check`: файл на каждый язык, разделы только версий из `CHANGELOG.md`,
   типографика zh/ja как в руководстве.
5. **Rust.** `check_update` добавляет в `UpdateCheck::Available` поле `notesI18n` — строковые непустые значения
   `notes_i18n` из `raw_json`; у старых релизов поле пустое.
6. **Фронтенд.** Заметки: `notesI18n[язык интерфейса] ?? notesI18n.en ?? notes`. Смена языка перерисовывает их без
   новой проверки. Рендер — react-markdown (без HTML и картинок, https-ссылки — в системный браузер) отдельным
   ленивым чанком, как справка; сбой чанка — тот же текст в `<pre>`. Блок — `section` с `aria-label`
   «Что нового в версии X» (новый ключ `about.updates.notesAria` во всех словарях).

## Совместимость
- 0.4.0 и 0.5.0 показывают `notes` как есть: английский Markdown, читаемый и моноширинным.
- Заметки на языке интерфейса появятся у тех, у кого уже стоит версия с этим изменением (обновление 0.6 → 0.7).
- Зеркала из политики (`updateUrl`) копируют тот же единственный `latest.json` — второго файла нет.

## Отвергнуто
- Разделы по языкам внутри `notes`: старые версии показали бы все 12 языков сырым текстом.
- Отдельный ассет `release-notes.json`: второй запрос из приложения, зеркала должны копировать ещё один файл.

## Проверки
`pnpm test:scripts` (разбор раздела, `notes_i18n`, проверки релиза и i18n), `cargo test --lib` (чтение `notes_i18n`
из `raw_json`), vitest «О программе» (язык интерфейса, запасной английский, старый формат, Markdown).
